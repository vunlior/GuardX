# Security Policy / Политика безопасности

## English

If you find a vulnerability in GuardX (for example a way to crash the server through the packet layer, bypass all checks, escalate permissions through commands or the API, or leak data through alerts or logs), please **do not open a public issue**.

Report it privately to the author, Vunlior: **vunlior@gmail.com**

Please include:
- GuardX version and server software/version (`/guardx diagnostics` shows the active packet layer);
- steps to reproduce, and logs if you have them;
- whether PacketEvents is installed.

Reports about ordinary cheat bypasses or false positives are not vulnerabilities: please send them as normal bug reports.

Only the latest release is supported with fixes.

## Русский

Если вы нашли уязвимость в GuardX (например, способ уронить сервер через пакетный слой, обойти все проверки, получить лишние права через команды или API, утечку данных через оповещения или логи), **не создавайте публичный issue**.

Сообщите автору, Vunlior, в личном порядке: **vunlior@gmail.com**

Укажите:
- версию GuardX, ПО и версию сервера (`/guardx diagnostics` показывает активный пакетный слой);
- шаги воспроизведения и логи, если они есть;
- установлен ли PacketEvents.

Обычные обходы проверок и ложные срабатывания уязвимостями не считаются: присылайте их как обычные сообщения об ошибках.

Исправления выпускаются только для последней версии.
